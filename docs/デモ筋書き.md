# デモの筋書き

約3分の動画で何を見せるか。**数字はすべて実際に走らせて確かめたもの**で、条件を添えた。

条件はどれも同じ日にそろえてある。

    日付 2026-10-16（金）／ 冬 ／ seed 20261015 ／ 保有6台

審査軸は3つ（課題の新規性・解決策の有効性／自律性・エージェントらしさ／実装品質・
拡張性）。幕ごとにどれを取りに行くかを決めておく。

## 2. 各幕の中身

### 幕1 — 朝の計画（40秒）

**実測**: 5台・9便・14軒・**156kL**、走行23時間4分。保有6台のうち5台を使う。

| 車 | 拘束 | 便 |
|---|---|---|
| 1号車（単車14kL） | 3時間38分 | 岩国装束運輸／錦町SS |
| 2号車（単車16kL） | 7時間34分 | 吉和・湯来 ／ 玖珂・周東 |
| 3号車（トレーラー18kL） | 7時間47分 | 宇品港 ／ 温品 |
| 5号車（トレーラー24kL） | 7時間35分 | 祇園 ／ 広島中央 |
| 6号車（トレーラー24kL） | 12時間37分 | 廿日市・観音新町 ／ 益田・浜田 |

言うこと:

- 5:00に車庫を出る（通勤混雑を避ける。24時間稼働の車だけ4:00から）
- **「必ず回る先」には理由が付く。** 欠品の直前／発注があった／計画配送、の3つだけ
- 労基法34条の休憩（6時間超45分・8時間超60分）と430休憩の大きいほうを取っている
- **需要はSSの規模から割り出している**（大型450／中250／小150 kL/月）。大型店は
  1日に十数kL売るので、タンクが持たず**毎日〜2日に1回**の配送になる

### 幕2 — FAXで当日発注（40秒）

**条件**: 09:12 に宇品港SSからFAX。**レギュラー8KL・灯油4KL**。
「連休で来客が多く、在庫が心もとないため追加します」。現物は `data/demo/fax_order.png`。

言うこと（**ここが一番効く**）:

- **発注は証拠の残る形でしか受けない。** 発注システムかFAX。**電話は不可**。
  電話の連絡は「予告」として試算までしかできず、車は動かさない（型で弾いている）
- 証拠はFAX画像のハッシュで紐づく。後から「どの発注で車を動かしたか」を辿れる
- **Gemini は書かれたとおり写すだけ。** 名簿の照合・油種の判別・KL→Lの換算は
  すべてコード。1つでも決められなければ確認を返し、組み直さない

**実測（2026-09-17・実Gemini）**: この画像を正しく読み取り、宇品港SSに照合、
証拠ハッシュ `FAX:b35e8bdfd2ab` を付けて発注2件にした。**13秒・0.0018 USD（約0.3円）**、
確認事項ゼロ。動画ではこの13秒を早送りするか、読み取り済みの状態から始める。

### 幕3 — 組み直し（60秒）

**実測（09:12・事象なし＝見込みのまま）**:

```
確認: 宇品港SS（24h） レギュラー: 発注 8.0kL のうち入る量が 4kL に満たないので車は出さない。
      タンクの空きが 2.6kL しかない（06:28 に3号車が 18.0kL 降ろす便が積込済み）。**SSに確認が要る**
確認: 宇品港SS（24h） 灯油: 発注 4.0kL のうち入る量が 4kL に満たないので車は出さない。
      タンクの空きが 0.3kL しかない（06:28 に3号車が 18.0kL 降ろす便が積込済み）。**SSに確認が要る**
```

**これがデモの山。** 断っているのではなく、**断る理由を名指ししている**——「あなたの
タンクは、6時28分に積み終えた3号車が18kL積んで向かっているので、もう空いていない」。
言われた量を運ぶ道具ではなく、**帳尻が合わないことに気づいて人に返す**。

**実測（FAXの但し書きを事象として当てる＝連休でガソリンが2日ぶん多く売れた）**:

```
変更: 宇品港SS（24h） レギュラー 8.0kL（当日発注・FAX FAX:b35e8bdfd2ab）: 5号車の2便目で 11:24 着
確認: 宇品港SS（24h） 灯油: 発注 4.0kL のうち入る量が 4kL に満たないので車は出さない。
      タンクの空きが 0.3kL しかない（…）。**SSに確認が要る**
```

**連休で出るのはガソリンで、灯油は出ない。** だからレギュラーは入り、灯油は入らない。
油種を指定せず「全油種2日ぶん」と当てると、2件とも 11:24 に入る。3通りを並べて、
**事象の当て方で答えが変わる**ことを見せてもよい。

あわせて言うこと:

- **非専属は呼んでいない。** その日の余力が20kLローリー1台ぶん以上残るので、専属の
  中で担当を替えて吸収した（広島中央SSを4号車→5号車の3便目へ）。**余力を割り込む日
  だけ、費用を払って非専属を呼ぶ**（車を1台に絞ると、同じ発注で非専属を2台呼ぶ）
- 朝の計画は組み直しの規則でも必ず成り立つ。**何も差し込まなければ朝の計画の担当が
  そのまま残る**（回帰テストで固定してある）

### 幕4 — 持ち戻り → 半期の体制設計（40秒）

**前半（持ち戻り）実測**: 宇品港SSで**灯油4kL（1槽ぶん）**が降ろせない。

```
先に降ろすことを優先し、近くの温品SS（日中）へ回します（12:08着、寄り道 +30分）。
この後の予定は30分ずれます。
費用は元売の管理責任（計画配送の先の在庫は元売が管理する）。運送会社・SSへの請求はありません。
```

- 順は 近くの降ろし先 → 大竹・岩国IC近くの大型SS → 積場へ持ち戻り（買い戻し）
- **持ち戻り品の処分が最優先。** 次の配送がずれても先に降ろす
- **槽は丸ごとでしか降ろせない**ので、持ち戻りは2kLの倍数でしか起きない

**後半（体制設計）実測**: 冬の半期・4エリア。

| | 専属 | 待機の非専属 | 応えられない日 |
|---|---|---|---|
| エリア間で融通しない | **15台** | **2台** | 1日/42日 |
| 完全に融通した場合 | **10台** | **1台** | 13日/42日 |

- **台数は需要から出る答え。** 1エリア（名簿15軒）は冬で6台
- **専属はピークに合わせない。** 故障の穴埋めに非専属を常時1〜2台確保する
- 数えるのは**欠品と、発注に応えられないこと**。計画配送を明日へ回すのは、在庫が
  切れない限り自由なので数えない
- 元売だけの最適化はしない。払う側の費用だけなら専属14台で、その差が運送会社に
  寄せているリスク

## 4. 撮る前に片付けること

- **本番は旧モデルのまま。** デプロイ済み（https://lorry-dispatch-125474373169.us-central1.run.app ）
  は main の 6bbc8d2＝規模を実務に寄せる前。新しいモデルは枝 `wip/demand-by-scale`。
  撮影前に main へ入れて再デプロイする
- **求解の時間**: 再現モードで106秒（Cloud Run のタイムアウト300秒に収まる）。
  即応モード（`mode=fast`）なら30秒で同じ計画に届く。動画では即応モードを使う
- **認証を外すかテストアカウント**が要る（審査員が触る面）
- 画面をどうするか（テキストのまま撮るか、簡単な画面を作るか）
