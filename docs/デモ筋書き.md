# デモの筋書き（案）

約3分の動画で何を見せるか。**数字はすべて実際に走らせて確かめたもの**で、出どころの
日付と条件を添えた。確かめていないものは「未測定」と書く。

審査軸は3つ（課題の新規性・解決策の有効性／自律性・エージェントらしさ／実装品質・
拡張性）。幕ごとにどれを取りに行くかを決めておく。

---

## 1. 先に結論

**推奨は4幕構成。** 前半3幕は「1エリアの1日」、最終幕だけ「運送会社の半期」に
スケールを上げる。

| 幕 | 見せるもの | 尺 | 取りに行く軸 |
|---|---|---|---|
| 1 | 朝の計画（必ず回る先と、その理由） | 40秒 | 有効性 |
| 2 | 09:12 FAXで当日発注が届く | 40秒 | エージェントらしさ |
| 3 | 組み直し。入る分だけ入れ、入らない分は**理由を添えて突き返す** | 60秒 | エージェントらしさ・有効性 |
| 4 | 持ち戻り → 逃げ道の恒常化 → 体制の見直し提案 | 40秒 | 新規性 |

**最終幕でスケールを上げるのは、ごまかしではなく必然。** 理由は §4 に実測で示す。

## 2. 各幕の中身

### 幕1 — 朝の計画（40秒）

**条件**: `2026-10-16`（金）・winter・seed 20261015・再現モード。

画面: 配車係の言葉で書き出した1日の計画。台ごとに便・立ち寄り・時刻・拘束時間。

言うこと:

- 5:00に車庫を出る（通勤混雑を避ける。24時間稼働の車だけ4:00から）
- **「必ず回る先」には理由が付く。** 欠品の直前／発注があった／計画配送の発注点割れ、
  の3つだけ。受入を見送ったSSには配車しない
- 労基法34条の休憩（6時間超45分・8時間超60分）と、430休憩の大きいほうを取っている

**実測（2026-09-12）**: 2台・4軒・38kL。v1 拘束3:50、v4 拘束10:17。求解3秒。

> **問題**: 4軒は画面として薄い。§4 の手当てを入れると 3台・7〜8軒になる。

### 幕2 — FAXで当日発注（40秒）

**条件**: 09:12 に宇品港SSからFAX。レギュラー 4KL、灯油 2,000L。
「連休で来客が多く、在庫が心もとないため追加します」。現物は `.scratch/fax_order.png`
（要・正式な置き場所への移動）。

画面: FAX画像 → 読み取り結果 → 発注として確定。

言うこと（**ここが一番効く**）:

- **発注は証拠の残る形でしか受けない。** 発注システムかFAX。**電話は不可**。
  電話の連絡は「予告」として試算までしかできず、車は動かさない（型で弾いている）
- 証拠はFAX画像のハッシュで紐づく。後から「どの発注で車を動かしたか」を辿れる
- **Gemini は書かれたとおり写すだけ。** 名簿の照合・油種の判別・KL→Lの換算は
  すべてコード。1つでも決められなければ確認を返し、組み直さない

**実測（2026-09-12・実Gemini）**: このFAXを正しく読み取り。1回約0.2円・**18秒**。

> **注意**: 18秒は生放送には長い。ここだけ早送りするか、読み取り済みの状態から始める。

### 幕3 — 組み直し（60秒）

**条件**: 09:12 時点で組み直し。積込を始めた便は動かさない。

画面: 変わったところだけを先に出す。

> **注意（2026-09-16）**: 槽の単位の直し（業務前提 §4.9）で名簿のタンク容量と配送量が
> 変わった。以下の時刻・量は直す前の測定で、**測り直しが要る**。FAXの「灯油2,000L」も、
> 灯油を2kLで頼むことは無い（実務）ので書き換える。

**実装済み（2026-09-15）**: FAXの但し書き「連休で来客が多く」を、日中に分かった事象
「見込みより売れた」として組み直しに渡す（`sold_more_now`、§5 案A）。朝の計画は見込みの
まま。

**実測（2026-10-16・09:12・宇品港SSがガソリンだけ見込みの2日ぶん多く売れた）**:

```
変更: 宇品港SS（24h） レギュラー 4.0kL（当日発注・FAX）: 1号車の2便目で 10:18 着
確認: 宇品港SS（24h） 灯油: 発注 2.0kL のうち入る量が 2kL に満たないので車は出さない。
      タンクの空きが 0.9kL しかない。**SSに確認が要る**
```

**この2行目がデモの山。** 発注を断っているのではなく、**帳尻が合わないことに気づいて
人に返している**——連休で出たのはガソリンで、灯油の空きは増えていない。言われた量を
そのまま運ぶ道具ではない。自律性はここで示す。

事象を当てない場合（見込みのまま）は2件とも「2kLに満たないので車は出さない」になり、
全油種に当てると2件とも 10:18 に入る。3通りを並べて見せてもよい。

**別案（§6の3の答え次第）**: 宇品港SSが朝から計画配送の日だった場合は、
「タンクの空きが 0.0kL しかない（07:07 に1号車が 3.2kL 降ろす便が積込済み）」と、
**向かっている車を名指しして断る**形になる（2026-09-12 に在庫を直接下げて確認）。
同じSSに計画配送と発注が同じ日に来ることがあるなら、こちらのほうが強い。

あわせて言うこと:

- 2kLに満たない量のために車は出さない（槽の単位でしか運べないため）
- 朝の計画は組み直しの規則でも必ず成り立つ。**何も差し込まなければ朝の計画がそのまま残る**
  （回帰テストで固定してある）

### 幕4 — 持ち戻り → 恒常化（40秒）

前半（持ち戻り、実務の優先順）:

- 降ろせなかったときの順は 近くの降ろし先 → 大竹・岩国IC近くの大型SS → 積場へ持ち戻り（買い戻し）
- **持ち戻り品の処分が最優先。** 次の配送がずれても先に降ろす。間に合わない先は
  他のローリーへ渡す
- **費用は元売の管理責任**で、運送会社・SSへの請求はない
- **槽は丸ごとでしか降ろせない。** 2kLなら近くのSSで捌けるが、4kLだと捌けない

**実測（2026-10-15・宇品港SSでレギュラーが降ろせない場合）**: 2kL槽なら近くの
広島中央SS（+44分）。4kL槽だと近くは最大3.5kLしか空きが無く全滅し、大竹IC近くの
大型SSへ（+139分、後の予定が139分ずれる）。
※ 日を2026-10-16に変えたときの数字は**未測定**。

後半（恒常化、**ここでスケールを上げる**）:

- 逃げ道（計画配送を明日へずらす）は**一時的なら可、恒常的なら構造の欠陥**
- 1日ずつ見ていると、どの日も「今日は仕方がない」で済む。**日をまたいで数えて
  初めて構造が見える**
- 半期の掃引で「専属を何台にすべきか」まで出す。**元売だけの最適化はしない**——
  運送会社側の稼働率と、逃げ道の日数を並べて出す

**実測（2026-09-12）**: 冬の半期・10エリアで**専属14〜20台**。融通しない場合は
専属20台・逃げ道0日。

## 4. 撮れないものと、その理由（実測）

デモを組もうとして、**当日発注に効く「事象」を表す入口が無い**ことが分かった。

### 4.1 発注が入る余地がない

いまの計画配送は3日周期でタンクを満たすので、**当日発注を入れる空きがタンクに
残らない**。2026-10-16 の宇品港SSの空きは レギュラー1.9kL・灯油0.9kL しかなく、
4kLの発注は「2kLに満たないので車は出さない」で終わる。

実際、**試したすべての発注が同じ結末**だった（浜田8/16kL、益田8kL、錦町4kL、
観音新町4kL、その組合せ。10-14/10-16、待機の非専属0台・1台）。どれも
「タンクの空きが1.2〜5.5kLしかない」で頭打ちになる。

**筋が通らない。** 当日発注が来るのは、**そのSSが計画より売れたから**（連休・値下げ・
寒波）。売れていれば空きがある。いまの生成器は「計画どおり売れた世界」しか作れない。

`generate()` が外から受け取れる事象は `absent_drivers`（欠勤）と
`declined_customers`（受入見送り）の2つだけ。**需要の急変を表す入口が無い。**

### 4.2 逃げ道が出ない＝恒常化の警告も出ない

逃げ道（計画配送を明日へ）は、**朝の計画に入っていた計画配送の先が、組み直しで
落ちたとき**に記録される。これが一度も起きなかった。3通り試した:

1. **在庫を減らす**（連休・寒波の模擬。50%／30%／15%）→ 逃げ道0
2. **乗務員を減らす**（欠勤0〜3名、使える車5→2台）→ 逃げ道0
3. **待機の非専属を用意する**（0台／1台）→ 一度も呼ばれない

理由は構造的。**名簿15軒はローリー2台ぶんの仕事しかなく、車は5台ある。**
車が足りなくなることが無いので、逃げ道を使う理由が生じない。車を2台まで減らすと
今度は**朝の計画の段階で**浜田SSが落ちるため、朝の計画に入っていない＝逃げ道とは
数えられない。

※ 在庫15%まで減らした時に浜田SSが「入らず」になったのは別の理由で、需要が
**36.2kL** と1台の容量（最大24kL）を超えたため。積み分け（2台で分けて運ぶ）を
モデルが持っていないので、誰にも運べない。**これは模擬のやりすぎで、実務の姿ではない。**

## 5. 手当ての案

### 案A（推奨）— 事象の入口を1つ足し、最終幕はスケールを上げる

1. **生成器に「今日この先は計画より多く売れた」を足す。** 津江さんに挙げていただいた
   引き金（連休・価格改定・寒波）そのもの。`absent_drivers` と同じ扱いで**外から
   与える事象**にすれば、「事象を入れたから計画が変わった」ことが切り分けられる。
   CLI・APIからも渡せる形にすれば、審査員が同じ画面を再現できる
2. **恒常化の警告は、1エリアの1日ではなく運送会社の半期で見せる。** 逃げ道は
   規模が効いて初めて出る。掃引（`scripts/size_carrier.py`）は既に半期42日中2日の
   逃げ道を出しており、**そこが恒常化監視の本来の居場所**

**利点**: 作るものが小さい（生成器に引数1つ）。嘘をつかない。最終幕が本プロジェクトの
差別化（体制設計層）に着地する。

### 案B — 名簿を運送会社1社ぶん（10エリア・150軒）に広げる

当日層でも車が足りなくなり、逃げ道が自然に出る。**利点**: 筋書きが一本で済む。
**欠点**: 求解時間が読めない（いまの重い試験日で5〜6分。150軒は未測定）。
締切まで1か月で、ここに踏み込むのは危ない。

**私の推奨は案A。** 案Bは提出後の拡張として README に書くのが妥当。
