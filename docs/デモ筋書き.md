# デモの筋書き

約3分の動画で何を見せるか。**数字はすべて実際に走らせて確かめたもの**で、条件を添えた。

条件はどれも同じ日にそろえてある。**数字は本番（Cloud Run）の出力で測り直した**
（2026-09-19、リビジョン 00008-2rk、画面つき・公開URL）。

    日付 2026-10-16（金）／ 冬 ／ seed 20261015 ／ 保有6台 ／ mode=reproducible

**再現モードで撮る。** 即応モードは実時間で打ち切るので、撮り直すたびに担当も時刻も
変わる。台本の数字が画面と食い違ってはどうにもならない。再現モードなら**何度撮っても
同じ計画**が出る（2026-09-19 に本番で2回連続、担当・便・時刻まで完全一致を確認）。

速さも問題にならない。**本番の実測（公開後・再現モード）**:

| 操作 | 待ち時間 | 内訳 |
|---|---|---|
| 朝の計画 | 71〜80秒 | 求解 71.1／70.5秒 |
| FAX1枚 → 読み取り → 組み直し | 75〜79秒 | 読み取りは Gemini で十数秒。**モデル費用 $0.0018（約0.27円）** |
| 持ち戻りの手を出す | 71秒 | 朝の計画を組み直してから探すため |

いずれも Cloud Run のタイムアウト（300秒）に余裕がある。**動画では待ち時間を早送りする**
（画面は待っている間、経過秒数を出し続ける。そこを映すと「考えている」ことが伝わる）。

**モードをそろえること。** 組み直しの土台は要求と同じモードで組む。画面の「求め方」を
再現のままにしておけば自動でそろう。即応で計画を見てから再現で組み直すと土台が別物になる。

**触れる場所**（審査員に渡すのと同じ）:

    https://lorry-dispatch-125474373169.us-central1.run.app/?k=marifu-lorry-2026

審査軸は3つ（課題の新規性・解決策の有効性／自律性・エージェントらしさ／実装品質・
拡張性）。幕ごとにどれを取りに行くかを決めておく。

## 1. 4幕構成

| 幕 | 見せるもの | 画面 | 尺 | 取りに行く軸 |
|---|---|---|---|---|
| 1 | 朝の計画（必ず回る先と、その理由） | 今日の配車 | 40秒 | 有効性 |
| 2 | 09:12 FAXで当日発注が届く | 当日の差し込み | 40秒 | エージェントらしさ |
| 3 | 組み直し。入る分だけ入れ、**入らない分は理由を添えて突き返す** | 同上 | 60秒 | エージェントらしさ |
| 4 | 持ち戻り → 半期の体制設計 | 持ち戻り → 端末 | 40秒 | 新規性 |

**一本の線でつながる。** 幕1で6号車の宇品港SS便を名指しし、幕3でその便に当日発注が
乗り、幕4でその便の荷が降ろせなくなる。**別々の機能を並べたのではなく、1台の1日**を
追う形にする。

### 幕1 — 朝の計画（40秒）

**実測**: 5台・9便・14軒・**156kL**、走行23時間4分。保有6台のうち5台を使う。

| 車 | 拘束 | 便 | 積む量 |
|---|---|---|---|
| 1号車（単車14kL） | 7時間53分 | 岩国装束運輸・錦町SS ／ 温品SS | 26.0kL |
| 2号車（単車16kL） | 7時間34分 | 周東SS・玖珂SS ／ 吉和SS・湯来SS | 32.0kL |
| 3号車（トレーラー18kL） | 3時間25分 | 祇園SS | 14.0kL |
| 5号車（トレーラー24kL） | 8時間11分 | 廿日市物流センター・観音新町SS ／ 広島中央SS | 46.0kL |
| 6号車（トレーラー24kL） | 12時間9分 | 益田SS・浜田SS ／ **宇品港SS** | 38.0kL |

**幕3・幕4は6号車の宇品港SS便の上で起きる。** ここで一度、名前を出しておく。

**画面**（タブ「今日の配車」）:

1. 上のフォームはそのまま（日付 2026-10-16／冬／seed 20261015／**求め方＝再現**）。
   「計画を組む」を押す
2. 待っている間、経過秒数が増えていく。**この数秒だけ映してから早送り**する
3. 「計画が出ました（求解 71.1秒）」と、その下に一文——
   「5台・9便で14軒。走行は合計23時間4分。必ず回るべき先はすべて回れます」。
   さらに小さく「**同じ入力で同じ計画が返るか: はい**」と出る。**ここを一度映す**——
   審査員が手元で同じ結果を出せることの申告で、実装品質の軸に効く
   （即応モードだと「いいえ（時間で打ち切った）」に変わる。**言えないことを言わない**）
4. 下へスクロールして車ごとの札を見せる。**1枚だけ大きく映すなら6号車**

   着／降ろす先／量／受入枠／余裕——**「余裕」が制約の効き方を一目で見せる**

言うこと:

- 5:00に車庫を出る（通勤混雑を避ける。24時間稼働の車だけ4:00から）
- **「必ず回る先」には理由が付く。** 欠品の直前／発注があった／計画配送、の3つだけ
- 労基法34条の休憩（6時間超45分・8時間超60分）と430休憩の大きいほうを取っている
- **需要はSSの規模から割り出している**（大型450／中250／小150 kL/月）。大型店は
  1日に十数kL売るので、タンクが持たず**毎日〜2日に1回**の配送になる

### 幕2 — FAXで当日発注（40秒）

**条件**: 09:12 に宇品港SSからFAX。**レギュラー8KL・灯油4KL**。
「連休で来客が多く、在庫が心もとないため追加します」。現物は `data/demo/fax_order.png`。

言うこと（**ここが一番効く**）:

- **発注は証拠の残る形でしか受けない。** 発注システムかFAX。**電話は不可**。
  電話の連絡は「予告」として試算までしかできず、車は動かさない（型で弾いている）
- 証拠はFAX画像のハッシュで紐づく。後から「どの発注で車を動かしたか」を辿れる
- **Gemini は書かれたとおり写すだけ。** 名簿の照合・油種の判別・KL→Lの換算は
  すべてコード。1つでも決められなければ確認を返し、組み直さない

**実測（2026-09-19・本番・実Gemini）**: この画像を正しく読み取り、宇品港SSに照合、
証拠ハッシュ `FAX:b35e8bdfd2ab` を付けて発注2件にした。**0.001787 USD（約0.27円）**、
確認事項ゼロ。読み取りから組み直しまで通しで75〜79秒。

**画面**（タブ「当日の差し込み」）:

1. タブを切り替えると、まず**断り書き**が出ている——「発注は証拠の残る形でしか
   受けません。電話で連絡が入っても、発注書が届くまで車は動かしません」。
   **ここを2秒静止**させる。幕2で一番効くのはこの一文
2. 「いまの時刻 09:12」「手元のサンプルを使う」にチェック（既定のまま）。
   **FAXの現物を先に1枚映す**（`data/demo/fax_order.png` を別窓で。手書きの
   「連休で来客が多く…」が読めるように）
3. 「読み取って組み直す」を押す → 経過秒数 → 早送り
4. 「読み取りと組み直しが終わりました（**モデル費用 0.27円ほど**）」。
   費用が画面に出ることも一言添える（暴走対策の台帳と同じ思想）
5. 「FAXから読み取った発注」の2行を映す——
   `c02　レギュラー　8.0kL（FAX・証拠 FAX:b35e8bdfd2ab）` / `c02　灯油　4.0kL（同）`。
   **証拠ハッシュが行ごとに付く**ところを指す

### 幕3 — 組み直し（60秒）

**実測（09:12・FAXの但し書きを当てない＝朝の見込みのまま）**:

```
09:12 時点で組み直しました。**発注量どおりに入らないものが1件あります（SSに確認）。**

確認: 宇品港SS（24h） レギュラー: 発注 8.0kL のうち入るのは 4.0kL。
      タンクの空きが 6.6kL しかない。**SSに確認が要る**
変更: 宇品港SS（24h） レギュラー 4.0kL（発注 8.0kL）（当日発注・FAX FAX:b35e8bdfd2ab）: 6号車の2便目で 14:05 着
変更: 宇品港SS（24h） 灯油 4.0kL（当日発注・FAX FAX:b35e8bdfd2ab）: 6号車の2便目で 14:05 着
```

**これがデモの山。** 8kL 頼まれて、**4kL だけ積み、残りは理由を添えて突き返す**。
全部を断ってもいないし、言われたまま運びもしない。

**なぜ 6.6kL 空いているのに 4kL なのか**——ここを説明できるかが勝負どころ。槽は
2kL と 4kL の組合せで積み、**その槽の全量が入らなければ、その槽は降ろさない**
（途中まで降ろして半端を持ち帰ることはしない）。そして**レギュラーのような量の出る
油種は 4kL 槽の単位で運ぶ**——2kL だけの荷降ろしは、流下の時間より準備と手仕舞の
手間のほうが大きいのでしない（実務）。だから 6.6kL の空きに入るのは 4kL 槽ひとつ、
「**4.0kL 入れて、残り 4.0kL はSSに確認**」になる。

**単位が実務どおりでなければ、この判断は出てこない。** kL を連続量として扱えば
「6.6kL 入れます」と答えてしまう。

言われた量を運ぶ道具ではなく、**帳尻が合わないことに気づいて人に返す**。

**この重なりの意味**（2026-09-19 確認）: 同じ先に同じ日の計画配送と当日発注が
両方立つのは、**無いことはないが、計画配送自体が甘かった**ということ（計画以上に
需要が発生した）。撮るときも「重なってはいけないものが重なった」ではなく、
**「甘かった計画の帳尻が当日に出た」**と言う。空きは一つしかないので、発注を
別口として足すことはできない——画面が名指ししているのは、まさにその一つの空きである。

**実測（FAXの但し書きを事象として当てる＝連休でガソリンが2日ぶん多く売れた）**:

```
09:12 時点で組み直しました。専属の余りで入ります。

変更: 宇品港SS（24h） レギュラー 8.0kL（当日発注・FAX FAX:b35e8bdfd2ab）: 6号車の2便目で 14:05 着
変更: 宇品港SS（24h） 灯油 4.0kL（当日発注・FAX FAX:b35e8bdfd2ab）: 6号車の2便目で 14:05 着
```

**当てると全量入る。** 見込みより2日ぶん多く売れた＝そのぶん在庫が減っている＝
**空きが増える**からで、8kL がまるごと入る。連休で出るのはガソリンなので、
当てるのはレギュラーだけでよい（灯油は連休では動かない）。

**同じ発注書でも、在庫の見立てが違えば答えが違う。** FAXの但し書き「連休で来客が
多く…」を読んで在庫の見立てを直すかどうかが、4.0kL と 8.0kL を分ける。**この2通りを
並べて見せるのが幕3の締め**——但し書きは人が読んで判断する材料で、当てるかどうかは
人が決める（画面の「見込みより売れた先を足す」の開閉で切り替わる）。

**画面**（同じ「当日の差し込み」タブ）:

1. まず**当てないまま**「読み取って組み直す」を押す（既定は「この事象を当てる」に
   チェックが入っているので、**外してから**押す）。結果は上の1つ目
2. 「確認が要るもの」の行を大きく映す。**ここが山**
3. 次に「見込みより売れた先を足す（連休・値上げ前・寒波）」を開き、
   需要家 c02／レギュラー／2日ぶん、「この事象を当てる」にチェック → もう一度押す
4. 結果が「専属の余りで入ります」に変わり、レギュラーが 8.0kL に増える。
   **2つの結果を左右に並べる編集**にすると一目で伝わる

あわせて言うこと:

- **非専属は呼んでいない。** その日の余力が20kLローリー1台ぶん以上残るので、専属の
  中で担当を替えて吸収した。**余力を割り込む日だけ、費用を払って非専属を呼ぶ**
  （車を1台に絞ると、同じ発注で非専属を2台呼ぶ）
- 朝の計画は組み直しの規則でも必ず成り立つ。**何も差し込まなければ朝の計画の担当が
  そのまま残る**（回帰テストで固定してある）

### 幕4 — 持ち戻り → 半期の体制設計（40秒）

**前半（持ち戻り）実測**（2026-09-19 本番・再現モード・71秒）: 6号車が宇品港SSで
**灯油4kL（1槽ぶん）**を降ろせない。**幕1で名前を出した6号車の、幕3で発注が乗った
その便**で起きる——ここが3幕つながる。

```
宇品港SS（24h）で灯油 4.0kL が降ろせません（持ち戻り、6号車）。先に降ろすことを優先し、
近くの温品SS（日中）へ回します（15:45着、寄り道 +15分）。この後の予定は15分ずれます。
費用は元売の管理責任（計画配送の先の在庫は元売が管理する）。運送会社・SSへの請求はありません。
```

- 順は 近くの降ろし先 → 大竹・岩国IC近くの大型SS → 積場へ持ち戻り（買い戻し）
- **持ち戻り品の処分が最優先。** 次の配送がずれても先に降ろす
- **槽は丸ごとでしか降ろせない**ので、持ち戻りは2kLの倍数でしか起きない

**画面**（タブ「持ち戻り」）:

1. 「降ろせなかった立ち寄り」の**プルダウンを一度開いて見せる**。中身は
   いま画面に出ている計画の立ち寄りそのもの（「6号車 — 宇品港SS（24h）（14:05着 18.0kL）」）。
   **配車係が知らない組み合わせを選べない**ことが、ここで伝わる
2. 6号車 — 宇品港SS を選び、油種＝灯油、量＝4kL（1槽）→「手を出す」
3. 結果の1行目（上の実測）を読み上げる。その下の**責任の所在の一文**も映す
4. 候補の表を全部映す。**14件のうち◎が1つ、×が10件、○が3件**
   （クッション2件＋積場への持ち戻り1件）。×には「空きが 0.4kL しかない
   （今日の予定を含む）」と**断る理由が1件ずつ付く**。
   **選ばなかった手まで理由つきで残す**のが要点

**後半（体制設計）実測**: 冬の半期・4エリア。

| | 専属 | 待機の非専属 | 応えられない日 |
|---|---|---|---|
| エリア間で融通しない | **15台** | **2台** | 1日/42日 |
| 完全に融通した場合 | **10台** | **1台** | 13日/42日 |

- **台数は需要から出る答え。** 1エリア（名簿15軒）は冬で6台
- **専属はピークに合わせない。** 故障の穴埋めに非専属を常時1〜2台確保する
- 数えるのは**欠品と、発注に応えられないこと**。計画配送を明日へ回すのは、在庫が
  切れない限り自由なので数えない
- 元売だけの最適化はしない。払う側の費用だけなら専属14台で、その差が運送会社に
  寄せているリスク

## 3. 撮れるもの・撮れないもの

| 幕 | 画面 | 状態 |

| 1 朝の計画 | タブ「今日の配車」 | **撮れる**（本番で確認済み・71秒） |

**幕4の後半だけ画面が無い。** 体制設計（半期に何台の専属を取るか）は当日の画面では

宇品港SS便に戻ってくる。**一度も画面を作り直さずに一本で撮れる**（タブを替えるだけ。
