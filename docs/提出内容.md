## 想定ユーザーと課題（フォーム本文）

石油ローリーの**二次配送**（油槽所からガソリンスタンド・運送会社営業所への配送）を
組む、運送会社の配車係のための道具です。

配車係は毎朝、次を同時に満たす組み合わせを紙と経験で見つけています。槽は1つに1油種
しか積めず、2kL・4kLの単位でしか降ろせない。需要家ごとに受入時間枠がある。乗務員の
拘束時間は改善基準告示と労働基準法の両方で縛られる。タンクが発注点を割れば今日行く
しかない。ここに寒波・値上げ前の駆け込み・欠勤・事故が乗ります。**1つ動くと全部が
動きます。**

この道具は、朝の計画を組み、当日入る発注や持ち戻りに合わせて組み直し、さらに
**日をまたいで「応えられなかった日」を数えます**。一日ずつ見ていると、どの日も
「今日は仕方がない」で済んでしまう。日をまたいで数えて初めて、一時的な逃げ道か、
体制（専属を何台取るか）の問題かが分かれます。

**いちばん効くのは、断れることです。** 8kLの発注に対し、タンクの空きが6.6kLでも、
レギュラーは4kL槽の単位でしか運びません。だから4kLだけ積み、残りは理由を添えて
突き返します。言われた量をそのまま運ぶ道具は、現場では使えません。

## 使った Google Cloud

| 要件 | 使ったもの | 使い方 |
|---|---|---|
| 実行環境 | **Cloud Run** | 画面とAPIを1サービスで（4vCPU・2GiB・同時実行1・最大3インスタンス） |
| AI | **Vertex AI / Gemini 3.8 Flash** | FAXの読み取りとメモの分類**だけ**。計算は一切させない |
| その他 | **Firestore** | コスト台帳と、応えられなかった日の記録 |
| その他 | **Cloud Build / Artifact Registry** | コンテナの構築と配布 |

**設計の中心にある一線**: Gemini がやるのは「紙に何と書いてあるか」まで。名簿の照合・
油種の判別・kL→Lの換算・積載・時刻・費用は、すべて決定論のコード（OR-Tools CP-SAT）が
行います。需要家の取り違えは配車の事故に直結するので、候補が1つに絞れなければ
**寄せずに確認を求めます**。

**同じ入力なら同じ計画が返ります。** 配車の最適解は同点が多く、実時間で打ち切ると
機械が違えば別の計画が出ます。探索量で打ち切る「再現モード」を用意し、計画自身に
「同じ入力で同じ計画が返るか」を申告させています（本番で2回続けて走らせ、担当・便・
時刻まで完全一致を確認済み）。
